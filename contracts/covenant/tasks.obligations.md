# covenant.tasks

## Purpose

The Mix tasks a project runs: `mix covenant.check`, `mix covenant.conditions`,
`mix covenant.regen` and `mix covenant.mutate`. Their contract is what a CI
step can rely on: what they print and their exit status.

## Obligations

### covenant.tasks.I1 — covenant.check runs the suite and reports
- **scope:** `mix covenant.check`, `Covenant.Relay`
- **must:** run the configured contract test paths as a `mix test` subprocess with `Covenant.Formatter`, relaying its output as text with valid UTF-8 unchanged and every invalid byte sequence as U+FFFD (a character cut between chunks held back until it is whole), so a test that prints binary data never stops the task (`Covenant.Relay`, which `mix covenant.mutate` uses for its workers too); print the coverage table and a warning for the components that declare no modules (`covenant.check: warning: N component(s) declare no modules: ...`, covenant.check.I11), write `<contracts dir>/coverage.json`, and exit 0 when the Contract holds; a `module` ceiling whose counter raises is a `covenant.check: warning: scope ceiling ... unchecked` line, not a failure, and does not stop `coverage.json` being written; run the suite with its results in a directory of its own under the results directory, so a `mix test` running in the background cannot overwrite them mid-run, then replace the Covenant result files of the results directory (`--results-dir`, `results_dir`, `COVENANT_RESULTS_DIR`) with them for a later `--no-run`, deleting only files that hold a Covenant results document, never recursing, never removing the directory and never touching another file
- **kind:** functional
- **record:** suite-runs-as-subprocess
- **status:** active

### covenant.tasks.I2 — covenant.check fails precisely on a broken Contract
- **scope:** `mix covenant.check`
- **must:** exit 1 printing each problem as `file:line: message` for a Contract that does not parse or does not hold; honour `--no-run` (read the last results) and `--contracts DIR`
- **kind:** functional
- **status:** active

### covenant.tasks.I3 — covenant.check fails when a contract test fails
- **scope:** `mix covenant.check`
- **must:** exit 1 when the suite exits non-zero, naming the failing test and its obligation
- **kind:** functional
- **status:** active

### covenant.tasks.I4 — covenant.conditions lists suspects and exits accordingly
- **scope:** `mix covenant.conditions`
- **must:** exit 0 when every machine-checkable premise holds, printing the counts (and every outcome with `--verbose`); exit 1 naming each suspect record at its line with the failing premise and reason. A condition that cannot be checked in this VM (a `value` check whose module is not compiled) is not counted as checked, does not fail the run, is counted on a `N condition(s) not checked in this VM` line and is listed with its reason by `--verbose`; a `value` check sees the modules of the project the task runs in
- **kind:** functional
- **status:** active

### covenant.tasks.I5 — covenant.regen writes a pack
- **scope:** `mix covenant.regen <component>`
- **must:** write the pack to `--out DIR` (default `tmp/covenant/regen/<component>`), list the files written, say which Public surface references it skipped: a `skipped (owned by <component>)` line per component that lists a module the surface mentions (covenant.regen.I9), a `skipped (already implemented in this project)` line, and how many others belong to modules the component does not own; say which modules it stubbed without being sure it owns them (a `possibly_foreign:` line); exit 0; exit 1 naming the problem for an unknown component
- **kind:** functional
- **status:** active

### covenant.tasks.I6 — covenant.check --static reads, never runs
- **scope:** `mix covenant.check --static`
- **must:** compile and run no contract test, and load neither the project's code nor its `runtime.exs` (a project whose `lib/` does not compile yet can be checked); print the files, modules and tagged tests read, every problem as `file:line: message` relative to the root, the static coverage table, the skipped checks (the tests generated by a `for`, `Enum.each`, `if` and the like among them, as `N generated test(s)` with each `file:line`, uncredited and not failing) and the warning for the components that declare no modules; write `<contracts dir>/coverage.static.json` and leave `coverage.json` untouched; exit 0 when the Contract holds statically and 1 otherwise; honour `--contracts`, `--test-path` (repeatable) and `--root`
- **kind:** functional
- **record:** static-coverage-own-file
- **status:** active

### covenant.tasks.I7 — covenant.mutate credits kills the same whatever --jobs
- **scope:** `mix covenant.mutate`
- **must:** give every mutant the same verdict and the same killing tests with `--jobs 1` and `--jobs N`; with N > 1 each worker runs the tests from a private working directory (a symlinked view of the project root with a `tmp/` of its own, removed when the worker ends), so ExUnit's `:tmp_dir` paths are never shared between workers
- **why:** a `:tmp_dir` is created at `tmp/<module>/<test>` under the working directory of the OS process, so workers sharing the project clear and rewrite each other's files, and the failures that follow would be credited as kills
- **kind:** functional
- **status:** active

### covenant.tasks.I8 — covenant.mutate documents the survivors file
- **scope:** `mix help covenant.mutate`
- **must:** describe the survivors file: where it lives, the keys of an entry, every sort and what it means, and the exit status
- **kind:** functional
- **status:** active

### covenant.tasks.I9 — The configured test paths resolve against the root, whichever directory a task runs in
- **scope:** `mix covenant.check`, `mix covenant.check --static`, `mix covenant.regen`, `mix covenant.mutate`, `mix covenant.conditions`
- **must:** resolve the `file` conditions and the `mix.lock` that `mix covenant.conditions` reads against `Covenant.root/0`, not the working directory; search the configured `test_paths` relative to `Covenant.root/0`, so a task run from an umbrella app (`apps/<app>`) finds the contract tests that one run from the root finds (`covenant.check` hands `mix test` those paths relative to the working directory); search a `--test-path` typed on the command line relative to the working directory; let `--contracts` redirect the Contract without moving the root; resolve the file exception targets and `glob` ceilings of a run against `Covenant.root/0` too, as `--static` does, so a ceiling over `apps/*/lib/**/*.ex` counts the same from every directory
- **why:** in an umbrella `mix covenant.regen billing.invoices` run from `apps/billing` and `mix covenant.mutate core.tenancy` run from `apps/core` found no contract test, because `apps/*/test/contract` was expanded relative to the app directory
- **kind:** functional
- **record:** test-paths-resolve-against-root
- **status:** active
